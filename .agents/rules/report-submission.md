# Group report, viva and submission

## Assessment and report

- Use the existing four-member team; every member must understand the full solution.
- Total assessment: autograder 40, group report 10, individual Git 10, algorithm
  knowledge 20 and code comprehension 20. The assignment is 10% of the final grade.
- For each Q1-Q7, identify edited functions/code blocks, include a clear screenshot
  of actual autograder output, and explain logic, data structures and heuristic
  design in at most 200 words.
- End the report with the public repository URL, commit-history and contribution
  graph screenshots, a table of member names/student IDs/specific tasks, and the
  AI usage declaration with tool names and exact prompts.
- The PDF specifies a strict six-minute session per team with individual viva
  evaluation. Support understanding of all algorithms, states, edge cases and
  heuristic proofs, not only the member's own code.
- Read [git-ai-usage.md](git-ai-usage.md) for evidence integrity and
  [grading.md](grading.md) for the unresolved public-publication conflict.
- Do not guess identities, student IDs, group ID, repository visibility or results.
  Collect missing required information before producing the dependent final artifact.

## Submission packaging

- Submit two separate items, once per group:
  1. `Group_<ID>_Report.pdf`, as a standalone PDF.
  2. `Group_<ID>_Code.zip`, containing only `search.py` and `searchAgents.py`.
- Use the actual group ID; do not guess it.
- The ZIP must contain those two files at its root, taken from `src/`. Exclude
  the `src/` directory wrapper, framework, tests, layouts, README, instruction
  files, report, caches, dependencies, and all other files.
- Keep authorized report/evidence/submission artifacts outside `src/` so the
  supplied project remains intact. Do not submit, publish, or push merely
  because local implementation or packaging was authorized.
