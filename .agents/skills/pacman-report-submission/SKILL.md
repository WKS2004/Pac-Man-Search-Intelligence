# pacman report submission

Read the root [AGENTS.md](../../../AGENTS.md) and use the `report-submission` route in
[routing.md](../../routing.md). The universal rules and that route's focused
rules remain authoritative. Load only the references needed for this task.

Produce or review the requested assignment deliverables.

- Confirm artifact creation/editing is within the user's requested scope.
- Obtain actual group ID, names, student IDs and contributions where needed;
  infer none of them from BLUEVERSE or an initialization commit.
- Gather genuine Q1-Q7 results and screenshots. Label missing evidence instead
  of manufacturing it. Keep each question explanation within 200 words.
- Follow the report-submission and git-ai-usage rules for report content,
  contribution evidence and exact AI prompts. Use a document/PDF skill if
  authoring the final report benefits from its artifact workflow.
- For a requested ZIP, take the two allowed files from `src/`, store them as
  `search.py` and `searchAgents.py` at the archive root, then inspect its members.
  Keep output artifacts outside `src/` and exclude all other project files.
- Creating a local package does not authorize portal submission or publication.
  Preserve the recorded publication conflict until clarified.
- Validate the actual report/package and identify incomplete prerequisites before
  claiming submission readiness.
