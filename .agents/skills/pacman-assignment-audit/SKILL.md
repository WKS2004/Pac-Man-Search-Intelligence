# pacman assignment audit

Read the root [AGENTS.md](../../../AGENTS.md) and use the `assignment-audit` route in
[routing.md](../../routing.md). The universal rules and that route's focused
rules remain authoritative. Load only the references needed for this task.

Inspect the requested project scope without changing files.

- Use the repository map to locate `src/` and the guidelines source.
- Compare required Q1-Q7 functions against the current code, not a remembered
  starter state or README description.
- Separate unimplemented assignment work, defects in protected supplied code,
  environment limitations and grading/document discrepancies.
- Inspect test metadata as needed. If execution helps the review, use the
  read-only commands and safeguards in the testing rule.
- Report evidence paths, observed behavior, impact and the smallest next action.
  An audit does not authorize fixes, environment installation or report creation.
- For collaboration/report reviews, verify available local evidence and identify
  missing information without inventing group identities or remote visibility.
